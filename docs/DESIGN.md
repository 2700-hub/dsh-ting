# 设计

## 目标

让 dsh-tui 里的每条回答，能以**原文**送进播放器朗读；用户点一下（或按一下）就开始，
可调语速、有进度条、逐句点亮。

## 非目标

- 不做通用 TTS 服务，不接管别的程序的朗读
- 不改 dsh-tui 本体（只用插件接缝）
- 不碰会话存储格式（插件拿的是事件，不是文件）

## 两条链路

### 1. 插件（本仓库）

```
assistant/message
      │  messages.observe（grant: messages.observe.read）
      ▼
┌──────────────────────────┐
│ dsh-ting plugin          │
│  · 订阅会话 scope         │
│  · 保存最近一条回答原文    │
│  · 注册快捷键             │
└──────────┬───────────────┘
           │ 写 inbox.md + spawn
           ▼
```

### 2. 播放器（外部 `ting`）

GTK4 + GStreamer，负责合成、播放、语速、进度、逐句点亮。
插件不重复造播放器，只负责**把文本递过去**。

## 契约：插件 → 播放器

插件写出一个文件，然后启动播放器：

| 项 | 值 |
| --- | --- |
| 路径 | `~/.cache/ting/inbox.md` |
| 编码 | UTF-8 |
| 内容 | 最近一条回答的 Markdown 原文 |
| 启动 | `ting -f ~/.cache/ting/inbox.md` |

这样播放器可以独立开发、独立测试，插件不认识 GTK，也不需要 TUI 里跑音频。

## 用到的接缝

| 接缝 | 用途 | 成熟度 |
| --- | --- | --- |
| `messages.observe` | 拿回答原文 | 契约 C-042（`messages.dsh/v1alpha1`） |
| 键盘快捷键 | 触发朗读 | 稳定候选（接缝十二） |
| 条目渲染器（可选） | 给回答加「▶ 朗读」入口 | 稳定候选（接缝十三），但改造渲染有风险 |
| 侧栏 Panel（可选） | 播放控制面板 | 实验性 |

## 风险

1. **授权**：`messages.observe.read` 默认拒绝，装完要批准，否则订阅是空操作。
2. **实验性 API**：`@deepseek-harness-tui/dsh-tui/api` 仍是实验面，版本升级可能改。
3. **插件生命周期**：宿主崩溃隔离、连续崩溃 3 次本会话禁用 —— 开发时要盯着日志。
4. **只能改配置不能热装**：装完要 `/restart`，这点会影响开发迭代速度。

## 降级策略

插件不可用时，播放器仍能读：

- `ting`（最新回答文件）
- `ting -c`（剪贴板）
- `ting -s`（截屏 OCR）

所以插件是"更顺"，不是"唯一"。
