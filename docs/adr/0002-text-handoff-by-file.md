# 0002 · 插件与播放器之间用文件 + spawn 交接

- 状态：已采纳
- 日期：2026-10-20

## 背景

插件（Node 进程内）拿到文本后，要让播放器（GTK4 + GStreamer，独立 GUI）念出来。
两者是不同进程、不同运行时。

可选做法：

1. 插件里直接调 TTS HTTP 接口 + 自己播音频
2. 插件通过 stdin 把文本管道给播放器
3. 插件写一个文件，再 spawn 播放器读这个文件
4. 插件和播放器之间开 socket / D-Bus

## 决策

选 3：写 `~/.cache/ting/inbox.md`，然后 `spawn('ting', ['-f', path])`。

## 理由

- **解耦**：播放器能独立开发、独立测试，不需要 TUI 就能验证 UI 和音频
- **可调试**：出问题时文件还在，人能直接看"到底喂进去了什么"
- **可复用**：剪贴板、文件、OCR 三种来源都能走同一条播放链路
- **失败可见**：写文件失败能立刻报错，比管道断裂好定位

## 后果

- 需要处理并发：连续触发时后写的覆盖先写的 —— 以最后一次为准
- 需要清理：inbox 文件会被反复覆盖，不累积
- spawn 失败要提示用户，不能静默（例如播放器没装、PATH 不对）
- 播放器可以用 `-f` 独立启动，方便手动验证

## 被否决的方案

- **1 自己播**：插件跑在 TUI 里，塞音频播放会把终端体验搞坏
- **2 stdin**：可行，但调试时看不到内容，且播放器需要额外支持
- **4 socket**：为一个人的项目引入协议和端口管理，成本大于收益
