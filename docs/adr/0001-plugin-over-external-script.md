# 0001 · 用 TUI 插件，而不是外部脚本

- 状态：已采纳
- 日期：2026-10-20

## 背景

想把 dsh-tui 里的回答读出来。最初做的是外部脚本，试了四条路：

| 办法 | 结果 |
| --- | --- |
| 拖选复制 | 能用，但长回答要拖很久 |
| 截图 + OCR | 把工具调用、状态栏、命令回显一起念出来 |
| 读会话 JSONL | 退出才落盘，当前这条读不到 |
| 手动存文本 | 靠人记，忘了就一直是旧内容 |

根因是同一个：**外部程序看不到终端里的文字**。Wayland 不给全局鼠标钩子，
Konsole 也不提供读屏接口，dsh-tui 的点击只用来聚焦。

## 决策

写 dsh-tui 插件。插件跑在 TUI 进程内，通过 `messages.observe` 拿到
`assistant/message` 的原文，不需要任何"从屏幕上抠字"的手段。

## 后果

**好处**

- 拿的是原文，不是渲染结果：没有 OCR 错字，没有 UI 噪声
- 不依赖剪贴板，不需要用户动手选中
- 可以做"点某一段读某一段"这类交互

**代价**

- 要装插件：manifest + profile 注册 + 重启才生效
- `messages.observe.read` 默认拒绝，得显式授权
- 插件 API 有一部分还是实验性的（`tui.dsh/v1alpha1`），升版本可能改
- 插件崩了会影响 TUI 会话（宿主有隔离，连续崩溃 3 次本会话禁用）

## 备选

- **只做播放器**：已经有了（`ting`），但"怎么把文字喂进去"始终别扭
- **改 dsh-tui 本体**：能解决，但把用户绑死在 fork 上，不划算
